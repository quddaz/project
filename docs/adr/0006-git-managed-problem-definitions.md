# ADR 0006: Git 기반 문제 정의 관리

- 상태: Accepted
- 날짜: 2026-07-21

## 배경

MVP에서 문제 설명, 스타터 저장소, 실행 조건, 공개 테스트를 관리해야 한다. 별도 관리자 UI를 만들면 인증, 편집 검증, 감사 이력까지 새로운 제품 범위가 생긴다.

## 사용자 가치

문제와 테스트가 검토 가능한 변경 이력으로 관리되어 잘못된 문제 배포를 줄인다. 특정 제출이 어떤 문제와 테스트 버전으로 채점됐는지 재현할 수 있다.

## 결정

문제는 `problem.yaml`, `README.md`, `tests/`로 Git에서 관리한다. `problem-sync` CLI가 전체 정의를 검증하고 하나의 트랜잭션으로 DB에 반영한다. 애플리케이션 시작 시 자동 동기화하거나 관리자 수정 API를 제공하지 않는다.

## 선택 이유

- 코드 리뷰와 Git 이력으로 문제 변경을 추적할 수 있다.
- 문제 설명과 테스트를 같은 버전으로 관리한다.
- 관리자 UI 없이 MVP 범위를 유지한다.

## 검토한 대안

- 관리자 웹 화면: 운영 편의는 좋지만 초기 구현과 보안 범위가 크다.
- 애플리케이션 시작 시 자동 동기화: 편하지만 잘못된 정의가 서비스 시작을 막을 수 있다.
- DB 직접 수정: 빠르지만 검토와 재현이 어렵다.

## 결과

문제 변경은 Git과 배포 절차를 거쳐야 한다. 동기화 명령은 부분 반영을 허용하지 않으며 검증 실패 시 기존 DB 상태를 유지한다.
