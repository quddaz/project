# ADR 0003: Docker 런타임 테스트 주입

- 상태: Accepted
- 날짜: 2026-07-21

## 배경

사용자는 공식 스타터 저장소를 fork하지만 저장소 안의 테스트를 수정하거나 삭제할 수 있다. 사용자 코드는 신뢰할 수 없으며 호스트에서 직접 실행할 수 없다. 테스트는 학습을 위해 공개하되 채점본의 무결성은 서버가 보장해야 한다.

## 사용자 가치

모든 사용자가 같은 테스트로 공정하게 채점받으며, 자신의 저장소에서 테스트를 실수로 변경해도 서버의 기준은 변하지 않는다. 실패한 공개 테스트를 확인해 즉시 학습에 활용할 수 있다.

## 결정

문제 정의 저장소가 공개 테스트의 기준본을 보관한다. 워커는 제출 commit SHA를 checkout한 뒤 해당 문제 버전의 테스트를 런타임에 주입하고, 일회성 Docker 샌드박스에서 고정 Gradle 명령을 실행한다. 사용자 저장소의 테스트는 채점 기준으로 사용하지 않는다.

## 선택 이유

- 테스트 해시만 검사하는 방식보다 사용자 실수에 덜 취약하다.
- 서버가 테스트 버전을 제출 결과와 연결해 재현할 수 있다.
- Docker 자원 및 권한 제한으로 비신뢰 코드의 영향을 줄인다.

## 검토한 대안

- 사용자 저장소 테스트 실행: 테스트 삭제만으로 통과할 수 있다.
- 테스트 파일 해시 검사: 사소한 변경도 제출을 막고 유지보수가 어렵다.
- 호스트 직접 실행: 격리와 자원 통제가 부족하다.

## 결과

채점 이미지, 테스트 주입 경로, Gradle 캐시를 운영해야 한다. Docker만을 완전한 보안 경계로 간주하지 않고 비특권 사용자, 네트워크 차단, capability 제거, 자원 제한을 함께 적용한다.
