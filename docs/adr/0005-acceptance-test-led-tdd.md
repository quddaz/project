# ADR 0005: RestAssured 중심 인수 테스트 TDD

- 상태: Accepted
- 날짜: 2026-07-21

## 배경

서버의 핵심 가치는 사용자가 로그인하고 문제를 조회하며 저장소를 제출하고 결과를 확인하는 전체 흐름에 있다. 계층마다 같은 동작을 반복 검증하면 테스트 유지비가 커진다.

## 사용자 가치

내부 구현을 바꿔도 실제 REST 사용 흐름이 보존되는지 빠르게 확인할 수 있다. 회귀 오류가 사용자에게 도달하기 전에 발견된다.

## 결정

RestAssured 인수 테스트를 TDD의 바깥 루프로 사용하고 플랫폼 서버 테스트 DB는 H2를 사용한다. 컨트롤러 단위 테스트와 단순 CRUD 리포지토리 테스트는 작성하지 않는다. 서비스는 통합 테스트를 우선하며 외부 API와 Docker만 필요한 범위에서 대역으로 교체한다.

MySQL의 `SKIP LOCKED`, 잠금, 동시 작업 선점은 특수성이 있으므로 해당 저장소 테스트에 한해 Testcontainers MySQL을 사용한다. 사용자 제출 코드의 JUnit 테스트는 플랫폼 테스트와 분리하며 H2를 사용하지 않는다.

## 선택 이유

- 사용자 시나리오와 API 계약을 한 테스트에서 검증한다.
- 구현 계층에 결합된 중복 테스트를 줄인다.
- 대부분의 테스트는 H2로 빠르게 실행한다.
- DB별 동작은 실제 MySQL로 확인해 잘못된 신뢰를 피한다.

## 검토한 대안

- 모든 계층의 단위 테스트: 피드백은 세밀하지만 중복과 리팩터링 비용이 크다.
- 모든 테스트에서 MySQL 사용: 일관성은 높지만 기본 피드백 주기가 느려진다.
- H2만 사용: MySQL 잠금과 인덱스 동작을 보장하지 못한다.

## 결과

인수 테스트가 지나치게 큰 시나리오가 되지 않도록 한 행동과 결과에 집중한다. 내부 로직이 복잡해질 때만 도메인 또는 서비스 테스트를 안쪽 루프로 추가한다.
