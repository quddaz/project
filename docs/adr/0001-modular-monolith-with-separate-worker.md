# ADR 0001: Gradle 멀티모듈과 API·워커 분리

- 상태: Accepted
- 날짜: 2026-07-21

## 배경

초기 서비스는 동시 채점 1~3건의 소규모 베타지만, 사용자 요청을 처리하는 웹 API가 비신뢰 코드를 실행하는 채점 부하와 장애에 영향을 받아서는 안 된다. 처음부터 여러 마이크로서비스를 운영할 인력과 규모는 없다.

## 사용자 가치

채점이 오래 걸리거나 실패해도 문제 조회와 제출 이력 확인은 안정적으로 사용할 수 있다. 사용자가 늘면 전체 서비스를 다시 만들지 않고 워커만 추가해 대기시간을 줄일 수 있다.

## 결정

하나의 Gradle 멀티모듈 저장소를 사용하되 API와 채점 워커를 별도 Spring Boot 프로세스 및 Docker 컨테이너로 실행한다. 공통 도메인과 유스케이스는 모듈로 공유하며 API는 Docker를 직접 실행하지 않는다.

## 선택 이유

- 단일 저장소로 코드 계약과 배포 버전을 맞추기 쉽다.
- 프로세스 분리로 웹 요청과 채점 실행의 장애 경계를 확보한다.
- 워커 컨테이너만 복제해 처리량을 늘릴 수 있다.

## 검토한 대안

- 단일 Spring Boot 프로세스: 단순하지만 채점 부하와 장애가 API에 전파된다.
- 완전한 마이크로서비스: 격리는 좋지만 초기 배포와 관측 비용이 과도하다.

## 결과

모듈 경계와 의존 방향을 관리해야 하며 API와 워커를 각각 배포해야 한다. 대신 초기 운영 복잡도를 제한하면서 확장 경계를 확보한다.
