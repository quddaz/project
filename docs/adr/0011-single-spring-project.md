# ADR 0011: 단일 Spring Boot 프로젝트와 워커 실행 분리

- 상태: Accepted
- 날짜: 2026-07-22
- 대체: ADR 0001의 Gradle 멀티 모듈 결정

## 배경

초기 설계는 도메인, 애플리케이션, 인프라, API, 채점, 워커를 Gradle 멀티 모듈로 분리했다. 현재 범위에서는 모듈 간 배포와 의존성 관리가 기능보다 복잡하고, 사용자가 참고하는 일반적인 Spring 프로젝트 구조와도 거리가 있다.

## 결정

Gradle 프로젝트는 루트 `build.gradle` 하나만 사용한다. 모든 기능은 루트 `src/main/java` 아래의 패키지 경계로 분리한다. API와 채점 워커는 같은 빌드 산출물을 공유하되 서로 다른 프로세스·실행 프로필로 구동할 수 있게 설계한다. 문제 동기화 CLI도 같은 코드베이스의 별도 main class로 유지한다.

## 이유

- `spring-roomescape-admin`과 같은 단일 Spring 프로젝트 구조를 따른다.
- 초기 기능 개발과 로컬 실행이 단순해진다.
- 패키지 경계만으로도 서비스·인프라·표현 계층을 분리할 수 있다.
- 워커 확장은 Gradle 모듈 복제가 아니라 프로세스와 컨테이너 수평 확장으로 처리한다.

## 결과

루트에서 `./gradlew bootRun`, `./gradlew test`, `./gradlew bootJar`를 실행한다. API와 워커의 실행 진입점 및 프로필 분리는 후속 채점 워커 구현에서 확정한다. 규모가 커져 독립 배포나 의존성 격리가 실제 병목이 되면 별도 ADR로 멀티 모듈 전환을 다시 검토한다.
