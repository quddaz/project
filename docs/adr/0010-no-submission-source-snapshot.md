# ADR 0010: 제출 소스 스냅샷 미보관

- 상태: Accepted
- 날짜: 2026-07-22
- 관련 결정: ADR 0003, ADR 0009

## 배경

채점에 필요한 `Application.java`는 사용자의 공개 GitHub 저장소에 이미 존재한다. 제출 소스를 DB에 복사해 보관하면 저장 공간, 개인정보·보안 관리, 보관 기간 관리가 추가로 필요해진다.

## 사용자 가치

사용자는 GitHub에 제출한 커밋을 기준으로 결과를 확인할 수 있고, 서버는 불필요하게 소스 코드를 장기 보관하지 않는다. 채점 이력은 남기므로 어떤 커밋과 어떤 공식 테스트로 판정했는지 재확인할 수 있다.

## 결정

`Application.java`를 포함한 제출 소스는 DB에 저장하지 않는다. 워커가 제출된 GitHub 저장소의 특정 커밋 SHA를 임시 작업 디렉터리에 clone한다. 이후 문제 버전의 공식 `ApplicationTest.java`를 `src/test/java/ApplicationTest.java`에 주입하고, 고정된 Docker 환경에서 다음 명령을 실행한다.

```text
./gradlew test --tests ApplicationTest
```

채점이 끝나면 작업 디렉터리와 clone된 소스는 삭제한다. DB에는 저장소 URL, 커밋 SHA, 문제 버전, 테스트 번들 버전과 checksum, 상태, 표준 출력·오류 출력, 실패 요약, 실행 시간, 시작·종료 시각만 저장한다.

## 선택 이유

- GitHub 커밋이 제출 소스의 단일 원본이 된다.
- DB 용량과 소스 보관에 따른 보안·개인정보 부담을 줄인다.
- 커밋 SHA와 공식 테스트 checksum으로 동일 채점 조건을 추적할 수 있다.
- 고정된 작업 디렉터리와 Docker 실행 모델을 그대로 유지할 수 있다.

## 검토한 대안

- 제출 소스 전체를 DB에 저장: 재현성은 높지만 저장·보안 비용이 증가한다.
- 제출 소스 압축본을 오브젝트 스토리지에 저장: 대규모 운영에서 고려할 수 있으나 초기 범위에는 불필요하다.

## 결과

GitHub API 장애나 삭제된 커밋은 채점 오류로 처리할 수 있다. 결과 재현이 필요하면 저장된 commit SHA와 test bundle checksum으로 다시 checkout하고 실행한다. 소스 보관이 필요한 운영 정책이 생기면 별도 ADR로 보관 저장소와 보존 기간을 결정한다.
